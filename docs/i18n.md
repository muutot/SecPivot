# UI Language Decision

Status: decided (2026-09-09) — hardcoded Chinese is the product language.
Full i18n is deferred; see revisit conditions below.

## Rule

- User-facing strings are written directly in Simplified Chinese. There is no
  translation layer, locale switcher, or string catalog (`src` contains no
  i18n/gettext infrastructure — only unrelated `localeCompare` calls).
- Code identifiers, comments, commit messages, and skill references stay in
  English. UI text stays in Chinese. Do not mix languages inside one surface.
- New UI strings follow the existing terse label + description style of the
  surrounding panel or dialog.

## Rationale

- Single-author Chinese user base; every shipped surface is Chinese-only today.
- A translation layer would double every UI change (strings + catalog +
  per-locale verification) with no consumer yet.
- The compact visual language is tuned for CJK line-breaking and density;
  a second language would need its own layout pass.

## Revisit when

- A non-Chinese user base is requested, or a store listing requires it.
- Then: introduce one minimal catalog (e.g. a `src/lib/i18n/` map with a
  `t()` helper), migrate panel by panel, and add a locale round-trip test.
  Do not bolt a second language onto hardcoded strings piecemeal.
