## Important Details

- 10 patterns: (1) `.clone()` on large structures in hot paths/loops; (2) guards held across `.await`; (3) blocking I/O on main tokio runtime inside Tauri commands; (4) `unwrap()`/`expect()`/`panic!` in non-test code; (5) repeated full-database re-serialization on mutations/saves; (6) O(N²) loops over entries/groups; (7) clipboard traffic/leaked handles; (8) secrets copied to non-zeroized `String` or logged; (9) timer/counter off-by-one, unsigned `now - deadline` overflow, duration math; (10) Vec/HashMap indexes rebuilt per call.
- Tauri v2 behavior (basis of the HIGH finding): sync `#[tauri::command]` fns run on the **main thread**; only `async` fns run on the async runtime. The repo already uses `async` + `spawn_blocking` in `update_database_settings` (commands/vault.rs:212/235), `refresh_remote_vault` (:299/312), `merge_remote_vault` (:325/338), `check_hibp` (entries.rs:133/145), `download_favicons` (favicon.rs:295), `remote.rs:67/146`, and `remote/mod.rs:94`. The five heavy **sync** commands are the inconsistency.
- Architecture: session mutex is `std::sync::Mutex<VaultSession>` (never held across `.await` — all async commands lock, extract a job, drop the guard, then `spawn_blocking`); `with_vault_session`/`with_resolved_vault_session`/`with_session_mut` in commands/mod.rs; `PersistenceGate`/`PersistencePermit` (Condvar) in vault/sessions.rs (gate acquire uses `spawn_blocking`, `acquire_persistence_async` included); process-wide shared blocking reqwest client behind `OnceLock` in remote/mod.rs (never dropped on the async runtime); async commands wrap storage ops in `spawn_blocking`.
- Confirmed clean / intentional: `util.rs::atomic_write` (temp sibling + `sync_all` before rename); `platform/clipboard.rs` Open/CloseClipboard correct on all paths (no handle leak); OTP time math `valid_for = period - (unix_time % period)` (otp.rs ~303, no underflow); `serialize.rs:278` `catch_unwind` in `attachment_size` documented/intentional (keepass store quirk); `primitives.rs` `random_bytes` `.expect` on getrandom (fatal OS-RNG failure, acceptable); HIBP k-anonymity (`breach.rs` `prefix_of` slicing safe); zeroization: persist.rs zeroizes password/keyfile clones, credential.rs zeroizes password, change_master_key zeroizes on both success (moved into session) and failure paths; config creds DPAPI-encrypted at rest (config/store.rs); `merge.rs` bin-detach (non-tracking `remove`) vs. propagating deletions (`track_changes().remove()`) correct; `s3.rs:173` `Method::from_bytes(...).expect("valid method")` compile-time constant, fine.
- Constants/contracts: timeouts 15s/30s/120s (remote/mod.rs); `REMOTE_CHANGED_MARKER="REMOTE_CHANGED\n"`; `SAVE_FAILURE_READ_ONLY_LIMIT=3`; `MAX_TEXT_IMPORT_BYTES=8MiB` + `.csv`/`.xml` whitelist; `PREVIEW_MAX_BYTES=2MiB`; `MAX_IMPORT_BYTES=64MiB`; `HIBP_RANGE_URL="https://api.pwnedpasswords.com/range/"`; `DEFAULT_BACKUP_TEMPLATE="{name}.{timestamp}.{ext}.bak"`; `GLOBAL_AUTOTYPE_SEQUENCE="{USERNAME}{TAB}{PASSWORD}{ENTER}"` (lib.rs:32 + commands/vault.rs); `ROOT_GROUP_UUID="root"`; `BROWSER_VAULT_CHANGED_EVENT="browser-vault-changed"`.
- Platform/security facts: `shield.rs` toggles `WDA_EXCLUDEFROMCAPTURE` (0x11) on window "main" while any vault open; `focus.rs` sends one `WM_CHAR` per UTF-16 unit (bypasses keyboard hooks); `autotype.rs` via `enigo` on a background thread (~1500 ms delay; password String moved into thread closure — secret stays on the heap until thread ends, inherent String design); DPAPI prefix `dpapi1:` (Windows) else plaintext; `otp.rs` field contract `otp`/`TimeOtp`/`HmacOtp`/`SteamOtp`/`steam`; favicon fetch uses WinINET proxy and semaphore-limited fan-out.

- Final findings (deliverable, ready to present):
  1. **HIGH (perf/UI freeze)** — `commands/vault.rs` `open_vault` (line 38, → `prepare_local_open`: file read + Argon2 KDF + KDBX parse), `create_vault` (line 80, → `prepare_local_create`: KDF + serialize + write), `save_vault` (line 259, → `persist_save`), `save_vault_as` (line 362), `change_master_key` (line 396, → `persist_change`) are **sync** Tauri commands → run on the main thread → Argon2 KDF (seconds) + full serialization + disk/network write freeze the UI. Session lock is correctly released, but the thread is still blocked. Fix: `async fn` + `tauri::async_runtime::spawn_blocking` for the heavy step, then re-lock for completion — mirror `refresh_remote_vault`.
  2. **MEDIUM (perf)** — `vault/security.rs:615-628` `similar_passwords` O(N²) pairwise `levenshtein_at_most` under the session lock on the main thread (sync command `commands/entries.rs:84` holds the mutex through `with_vault_session`). 2000-entry cap; length-diff prefilter (:617) rejects most pairs, but a vault with many same-length passwords still runs Levenshtein on ~2M pairs, each allocating. Fix: `spawn_blocking` on a cloned password list (zeroized after) or async command.
  3. **MEDIUM (bug)** — `remote/s3.rs:105` `host_header` `expect("endpoint was validated")` — endpoint is only checked non-empty in `S3Storage::new` (:39); a scheme-less endpoint like `minio.local` passes settings, then panics in `send()`. Panic is contained by `spawn_blocking` (surfaces as generic "任务异常" JoinError), so no crash — but it is a panic on user-configurable input with a misleading message. Fix: validate/parse endpoint URL in `new` with a clear error.
  4. **LOW (bug)** — `crypto/otp.rs:108` `pad_code` `10u32.checked_pow(digits).unwrap_or(u32::MAX)` — digits ≥ 10 → wrong modulo (u32::MAX) and a `digits`-wide zero-pad. `totp_code`/`hotp_code` accept arbitrary frontend `digits`. Fix: clamp 1..=9 (error or clamp).
  5. **LOW (memory)** — `favicon.rs` `fetch_favicon` reads the full body (`response.bytes()`) before the 512 KiB cap check; huge body buffered (bounded only by the 20 s timeout). Fix: reject via `Content-Length` header first, or `take(limit+1)`.
  6. **LOW (pattern 4, logic-invariant)** — `commands/vault.rs:421/423` `expect("password is available")`/`expect("keyfile is available")` (fires only if `complete_change` consumed one slot but not the other); `vault/entries.rs:182` ("validated entry must exist") and `:821` ("validated group must exist") (guarded by prior validation).
  7. **Notes (not findings)** — `session.rs:545-556`/`:561-571`/`:741` `prepare_save`/`prepare_save_as`/`prepare_change` clone the entire Database under the session lock — explicitly documented tradeoff (comment at :542-544); still couples with finding #1 (runs on the main thread). `security_report` holds plaintext passwords in a HashMap in-memory during analysis (by design, never serialized). `helpers.rs` `walk_ref_match` lowercases the password into a temporary String for URL matching (transient copy; could compare without copying). `hosts.rs` `collect_rpc_logins`/`collect_bridge_logins` clone passwords into DTOs crossing to the browser extension (required by protocol; recycle bin excluded from all read paths).
